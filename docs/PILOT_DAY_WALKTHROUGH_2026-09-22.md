# Watercooler Werewolf Pilot Walkthrough

- **Pilot date:** Tuesday, September 22, 2026
- **Game timezone:** America/Regina
- **Production site:** <https://watercooler-werewolf-dyl-edge.vercel.app>
- **Moderator console:** <https://watercooler-werewolf-dyl-edge.vercel.app/moderator>
- **Returning-player sign-in:** <https://watercooler-werewolf-dyl-edge.vercel.app/player-login>

This is the moderator's start-to-finish checklist for the human pilot. Keep this page open on a private moderator device. Do not project or share the moderator console because it displays every player's role.

## The five rules to remember

- [ ] Use **Production**, not a Preview URL.
- [ ] Have at least **six human players**. The live app does not currently provide player bots.
- [ ] Do not release roles until every expected player is present and every seat says **CLAIMED**.
- [ ] A player has not voted or acted until they select **Save response**.
- [ ] For every phase, follow: **Open → collect responses → lock and calculate → resolve Hunter if prompted → review → publish**.

## Choose the purpose of this pilot

Make this choice before importing the roster.

### Recommended: normal human pilot

Accept the role preset generated by the app. For six players, that is:

- 1 Werewolf
- 5 Villagers

This is the cleanest way to evaluate joining, secrecy, discussion, voting, moderation, publication, and completion. It will not exercise Seer, Bodyguard, or Hunter gameplay at six players.

### Alternative: special-role workflow test

If seeing every special-role workflow is more important than normal balance, manually use:

- 1 Werewolf
- 1 Seer
- 1 Bodyguard
- 1 Hunter
- 2 Villagers
- 0 Masons

This configuration is intentionally Village-heavy and is a feature test, not a fairness recommendation. If the Werewolf is eliminated during the first Day, the game will end before Night. Do not secretly alter a genuine player vote just to keep the test running; run a separate rehearsal if necessary.

## Before participants arrive

### 1. Confirm attendance and devices

- [ ] Confirm at least six players will attend.
- [ ] Confirm every player has their own phone, computer, or isolated browser profile.
- [ ] Do not sign multiple players into ordinary tabs in the same browser profile; they will share a session.
- [ ] Keep the moderator on a separate device or browser profile.
- [ ] Choose the external discussion channel: in person, Teams, Slack, or another agreed location.
- [ ] Decide approximately when the last normal phase should end.

If fewer than six people are available, do not release roles. The supported roster minimum is six and there are no live-game bots to fill missing seats.

### 2. Sign in to the moderator console

1. Open the [Production moderator console](https://watercooler-werewolf-dyl-edge.vercel.app/moderator).
2. Enter the moderator email and password.
3. Select **Sign in**.
4. Confirm the page shows the Production game workspace and no error banner.

### 3. Create the game schedule

1. Select **Start new setup**.
2. Under **Schedule the campaign**, enter:
   - **Game name:** a clear name such as `September 22 Human Pilot`
   - **Timezone:** `America/Regina`
   - **Start date:** `2026-09-22`
   - **End date:** `2026-09-22`
   - **Final cutoff:** the time you want to permit the closing Final showdown
   - **Day ballot closes:** leave `16:00` unless you want a different displayed cadence
   - **Night actions close:** leave `09:00` unless you want a different displayed cadence
   - **Active weekdays:** select **Tue**
3. Select **Create game**.

The dates are required setup information, but they do not force you to wait between ordinary phases. Every live phase gets its own future deadline. You may manually lock a phase before that deadline when everyone is finished.

Set the **Final cutoff** before releasing roles. Final showdown cannot begin until that timestamp has passed, and the schedule becomes read-only after roles are released. If you want to test Final showdown during a short session, set the cutoff before the expected final portion of the pilot.

### 4. Import the roster and save the invitations

1. Prepare one CSV row per player using exactly this format:

   ```csv
   display_name,email
   Alex Example,alex@example.com
   Blair Example,blair@example.com
   ```

2. Replace the sample text under **Roster CSV** with the complete real roster.
3. Select **Create private seats**.
4. Immediately select **Download invite CSV**.
5. Store the downloaded file privately. It contains access information for every player.
6. Send each player only their own `claim_url` and `invite_code`. The app does not send invitations automatically.

Do not re-import the roster casually. Re-importing before launch replaces the seats and invalidates the invitations you already distributed.

## As participants arrive

### 5. Have every player claim their seat

Tell each player to do the following privately:

1. Open their personal `claim_url`.
2. Confirm their own name and the correct game name appear.
3. Choose a six-digit PIN they can remember.
4. Select **Claim my seat**.
5. Select **Enter the game**.
6. Keep the invite code and PIN private.

For a later return, players use the [player sign-in page](https://watercooler-werewolf-dyl-edge.vercel.app/player-login) with their invite code and six-digit PIN. They should not repeat the one-time claim process.

In the moderator console:

- [ ] Wait until the claim meter reads the full roster, such as **6 of 6 claimed**.
- [ ] Resolve any missing claim before continuing.
- [ ] Confirm every expected participant is physically present or connected.

### 6. Confirm the role composition

1. Scroll to **Balance the roles**.
2. Review the automatically populated counts.
3. Either keep the normal preset or enter the special-role test counts chosen above.
4. Confirm the total exactly equals the number of players.
5. If you changed any count, select **Save composition**.

The app requires at least one Werewolf, permits at most one Seer, Bodyguard, and Hunter, and permits either zero Masons or at least two Masons.

### 7. Randomize, privately review, and release

1. Confirm every seat is claimed.
2. Select **Randomize roles**.
3. Under **Review assignment batch**, confirm every player received exactly one role and the counts match the composition.
4. Use the first technically valid randomized batch; do not repeatedly reroll to place particular people in particular roles.
5. When everyone is ready, select **Release roles to players**.
6. Confirm the game becomes active.

Role release is the launch point. The roster, schedule, and composition become locked. Changing them afterward requires resetting the game and issuing fresh invitations.

## Read this briefing to the players

> Most players belong to the Village; the Werewolf is hiding among you. During each open phase, use the app to select your target and press Save response. Discussion or selecting a card does not count as a vote. You may revise a saved response until I lock the phase, and only your latest saved response counts. Keep your role, invite code, PIN, private rooms, and private results secret. The Theme switch is optional—leave it off if you do not want your screen's styling to hint at your role. Ask me privately if your page does not match these instructions.

Then ask everyone to:

- [ ] Find **Your private role** and read it silently.
- [ ] Confirm they can see the **Theme** switch near the top of the page.
- [ ] Leave Theme off or turn it on according to their privacy preference.
- [ ] Avoid holding a role-colored screen where others can see it.
- [ ] Identify **Today**, **Official timeline**, and **Private room** on their page.

The Theme setting starts off when the page is opened or reloaded.

## Run Day 1

### 8. Open the Day ballot

1. In the moderator console, scroll to **Run the live game**.
2. Confirm the offered phase is **Day ballot**. The first phase must be Day.
3. Set **Deadline** to a future time in `America/Regina`. Ten to fifteen minutes ahead works well for a short pilot.
4. Select **Open phase**.
5. Announce: “Day 1 is open. Discuss, select a player in the app, and press Save response before the displayed deadline.”

### 9. Collect Day responses

Each living player should:

1. Open **Today**.
2. Select one legal player card.
3. Select **Save response**.
4. Wait for the saved-revision confirmation.
5. Optionally change the choice and save again to test revision behavior.

As moderator:

- [ ] Watch **current responses** increase.
- [ ] For Day, expect one current response from every living player who participates.
- [ ] Remind the group that a highlighted card without **Save response** is not submitted.
- [ ] You may continue with missing responses, but those players will contribute no vote.

### 10. Resolve and publish Day 1

1. When everyone is done, select **Lock responses & calculate**. You do not have to wait for the deadline.
2. Review the vote tally, proposed elimination, unused slots, warnings, and any recorded tie draw.
3. If **Hunter follow-up required** appears, pause and follow the Hunter procedure below.
4. If the calculation is correct, select **Approve & publish**.
5. Confirm the phase says **PUBLISHED** and an authoritative outcome appears.
6. Ask players to verify the result appears in **Official timeline**.
7. Check whether the app declared a winner.

Never announce an elimination as official before selecting **Approve & publish**. Calculation alone does not apply the result.

## Hunter procedure

Use this only when **Hunter follow-up required** appears after calculating a phase.

1. Do not reveal the unpublished elimination to the whole group.
2. Say privately or generically: “If your dashboard now asks for a required follow-up, complete it and tell me when it is saved.”
3. The affected Hunter opens their dashboard.
4. The Hunter selects one eligible living target under **Choose your final target**.
5. The Hunter selects **Save response**.
6. In the moderator console, select **Finalize Hunter**.
7. Review the updated proposed outcome, including the Hunter's target.
8. Select **Approve & publish**.

If the Hunter does not respond, the moderator must wait until the displayed Hunter deadline before finalizing without a shot.

## Run Night 1

### 11. Open Night actions

If the game did not end after Day 1:

1. Confirm Day 1 is **PUBLISHED**.
2. The next offered phase should be **Night actions**.
3. Set a future deadline; five to ten minutes is reasonable for the pilot.
4. Select **Open phase**.
5. Announce: “Night is open. Check your own dashboard. If it gives you an action, select a target and press Save response. If it tells you to wait, do nothing.”

### 12. Collect Night actions

- Each living Werewolf submits a private attack ballot.
- The Seer, if present and alive, selects one player to investigate.
- The Bodyguard, if present and alive, selects one player to protect.
- Villagers, Hunters, and Masons have no ordinary Night action.

The Night **current responses** count will normally be lower than the number of living players. Do not wait for Villagers or other roles whose screens say to wait.

### 13. Resolve and publish Night 1

1. Select **Lock responses & calculate** when the eligible actors are finished.
2. Review the proposed attack, any protection, warnings, and the resulting elimination list.
3. Complete the Hunter procedure if prompted.
4. Select **Approve & publish**.
5. Confirm **PUBLISHED**, check for a winner, and have players inspect **Official timeline**.
6. If a Seer acted, ask the Seer—without asking them to reveal the content publicly—to confirm a new exact-role result appears in **Private result history**.
7. If a Bodyguard successfully protected a target, confirm the moderator result shows the protection and that the protected player survived that attack.

## Continue the game

### 14. Repeat Day and Night

Continue alternating:

1. Open the next offered phase with a future deadline.
2. Tell players to check their dashboards.
3. Collect and save responses.
4. Lock and calculate.
5. Resolve a Hunter follow-up if prompted.
6. Review and publish.
7. Check for a winner.

The app enforces **Day → Night → Day** and will not let you open the next phase until the current one is published. Eliminated players can spectate and use **Afterlife**, but cannot vote or use their former powers.

## Finish through Final showdown

Final showdown is optional. The game may end naturally before the cutoff.

### 15. Enter Final showdown

To test or use the closing sequence:

1. Wait until the configured **Final cutoff** has passed.
2. Finish and publish the current Day or Night phase.
3. Confirm there is no unresolved phase.
4. Select **Enter final showdown**.
5. Confirm the next offered phase is **Final ballot**.

If the button is rejected, either the cutoff has not passed or the latest ordinary phase is not published.

### 16. Run Final ballots

1. Enter a future deadline.
2. Select **Open phase**.
3. Every living player selects a target and presses **Save response**, just as during Day.
4. Lock and calculate.
5. Complete any Hunter follow-up.
6. Review and publish.
7. Repeat Final ballots if no winner is produced. There are no more Night phases after entering Final showdown.

## Close the pilot

### 17. Confirm completion

- [ ] Confirm the game status is **COMPLETED**.
- [ ] Confirm the winning faction appears in **Official timeline**.
- [ ] Confirm eliminated roles and the final result are visible to players.
- [ ] Confirm private rooms are read-only at completion.

### 18. Save evidence and feedback

1. In **Communications & operations**, select **Download JSON backup** and store it privately.
2. Ask every participant to complete **Pilot feedback** on their player page.
3. Record any confusing instruction, incorrect screen, delayed update, or error message.
4. Save screenshots only with participant permission and do not share private-role information publicly.

Suggested debrief questions:

- Could you claim your seat without help?
- Did you understand that **Save response** was required?
- Could you tell when a phase was open, locked, and published?
- Did the timeline explain what happened?
- Did the Theme switch feel useful and sufficiently discreet?
- Did any page reveal information you did not think you should see?
- What was the most confusing moment?

## Troubleshooting during the pilot

| Problem | What to do |
| --- | --- |
| Fewer than six players arrive | Do not release roles. There are no live player bots. Reschedule or add real test participants. |
| A player cannot claim | Verify they are using their own Production claim URL and that the roster was not re-imported. |
| A player already claimed but cannot return | Use `/player-login` with their invite code and PIN. |
| A player forgot their PIN | In **Player access recovery**, choose that player, set a new six-digit PIN, add a reason, and deliver it privately. |
| Randomize roles is disabled | Confirm every seat is claimed and any edited composition was saved. |
| Role counts will not save | Confirm all counts are non-negative integers and total the roster. Masons must be zero or at least two. |
| A player's role says not released | Confirm you selected **Release roles to players**, then have them refresh. |
| A player cannot save | Confirm the phase is open, the target is legal, the player is alive, and they selected a target. |
| Night responses seem too low | Only Werewolves, the Seer, and the Bodyguard normally act at Night. |
| Phase deadline error | Enter a deadline in the future using the timezone printed beside the field. |
| Hunter cannot be finalized | Wait for the Hunter's saved response or for the displayed Hunter deadline to pass. |
| Final showdown is blocked | Wait for the final cutoff and publish the current ordinary phase first. |
| A moderator action shows an error | Refresh and inspect the authoritative state before retrying; another request may already have succeeded. |
| A published result is wrong | There is no ordinary undo. Preserve the evidence and decide whether to continue or reset the game. |
| You need to temporarily pause | Stop opening phases. Do **not** select **Stop game**; Stop is permanent for that run and is not a pause. |

## If the pilot must be abandoned

1. Take a screenshot of the error without exposing credentials or private roles.
2. Record the exact time, selected game, phase, player role involved, and button pressed.
3. Download a backup if the moderator console still works.
4. Use **Stop game** only if you are intentionally ending the run; it cannot be resumed.
5. Do not select **Reset to setup** unless you intend to erase the active run and issue fresh invitations.
